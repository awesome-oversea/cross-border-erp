# OMS 订单风险检测设计
## 背景

OMS 已具备本地风控规则和 PMS 风险预警接入能力，但 `P2-025` 还缺少两项关键闭环：

- PMS 风险预警没有统一沉淀到订单风险检查记录
- 人工审核风险预警时没有持久化处理备注与时间，无法形成处理留痕

本次实现聚焦验收要求“风险检测产生风险等级、原因、建议动作；人工处理后留痕”，不扩展到外部审批中心。

## 四色建模

- 粉：风险命中时刻、PMS 预警接收时刻、人工审核时刻
- 黄：OMS 风控服务、订单运营人员、PMS 风险 Agent
- 蓝：本地风险检测、接收 PMS 风险预警、人工批准/驳回、记录处理日志、查询处理日志
- 绿：销售订单、订单风险检查、PMS 风险预警、PMS 风险处理日志

## 设计决策

### 1. 风险记录统一落到 `OrderRiskCheck`

本地规则命中和 PMS 风险预警都沉淀为 `OrderRiskCheck`，统一保存：

- 风险等级
- 风险类型
- 风险原因描述
- 建议动作

这样订单侧只需要查看一个风险记录列表即可满足验收中的“风险记录”。

### 2. 人工处理使用独立日志表

为避免覆盖历史审核结果，新增 `oms_pms_risk_alert_review_log`：

- `alert_id`
- `order_id`
- `action`
- `reviewer_note`
- `created_at`

主表 `oms_pms_risk_alert` 仍只保存当前状态，日志表负责留痕。

### 3. 审核动作显式校验

`reviewPmsRiskAlert` 只接受：

- `approved`
- `rejected`

非法动作直接拒绝，避免当前“非 approved 一律当 rejected” 的隐性错误。

### 4. 查询接口

新增日志查询接口：

- `GET /oms/api/in/v1/orders/risk-alerts/{alertId}/review-logs`

用于直接验证“人工处理后留痕”。

## 测试策略

- 接收 PMS 风险预警时写入 `OrderRiskCheck`，并在高风险时推进订单到待审
- 审核通过时写入处理日志，并回写订单风险等级
- 审核拒绝时写入处理日志，不丢失审核备注
- 非法审核动作抛出业务异常
- 日志查询接口返回按时间倒序的处理记录
