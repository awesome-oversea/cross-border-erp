# SCM 采购计划设计

## 背景

SCM 当前已经具备：

- 供应商档案、联系人、资质、评分维护
- 手工创建采购单、提交、审批、收货
- 补货建议生成与接受/拒绝

但 `P2-027` 还缺失真正的计划层，导致“订单需求 + 备货需求 + 库存/采购在途”之间没有统一汇总入口。采购人员只能手工录入采购单，不能形成生产上常见的“需求汇总 -> 采购计划 -> 采购单草稿”闭环。

本次实现聚焦验收要求“采购需求可从订单/备货汇总生成采购计划和采购单；数量计算正确”，不扩展到审批流、付款申请、收货异常。

## 四色建模

- 粉：订单下单时间、补货建议生成时间、采购计划生成时间、采购单创建时间
- 黄：运营人员、采购专员、供应链经理、系统聚合服务
- 蓝：汇总订单需求、汇总备货需求、扣减可用库存、扣减采购中数量、生成采购计划、按计划转采购单
- 绿：销售订单、补货建议、库存可用量、采购中数量、采购计划、采购计划行、采购单

## 设计决策

### 1. 新增“采购计划”层，不改写现有采购单模型

保留现有 `PurchaseOrder` 作为执行单据，新增：

- `PurchasePlan`
- `PurchasePlanLine`

采购计划负责沉淀“为什么要买、买多少、扣减过程是什么”；采购单继续负责“向哪个供应商下单、多少钱、何时收货”。

### 2. 订单需求通过 OMS 专用聚合接口提供

不让 SCM 直接解析 OMS 订单全量模型，新增 OMS 内部接口输出采购需求聚合：

- 按 `sellerSku` 汇总开放订单需求
- 返回订单数、需求数量、订单来源列表

这样跨域边界更清晰，也避免 SCM 与 OMS 订单结构强耦合。

### 3. 采购计划公式显式化

单个 SKU 的建议采购量使用统一公式：

`建议采购量 = max(订单需求量 + 备货需求量 - 可用库存 - 采购中数量, 0)`

其中：

- 订单需求量：OMS 开放订单聚合结果
- 备货需求量：SCM 中已接受的补货建议汇总
- 可用库存：WMS 可用库存
- 采购中数量：未取消、未完全收货的采购单未收数量

计划行必须保留这四个数字和来源明细，确保采购结果可追溯、可解释。

### 4. 采购计划转采购单采用“选行 + 指定供应商 + 指定单价”

由于当前系统尚未建立 SKU 到默认供应商/默认采购价的主数据映射，计划转采购单不做错误的自动选供应商：

- 采购员在计划转单时选择供应商
- 为每个计划行提供采购单价
- 系统按选中的计划行生成采购单草稿

这样既满足业务闭环，也不引入不可靠的自动分单规则。

### 5. 计划与采购单解耦，但保留关联

采购计划行会记录：

- `linkedPoId`
- `lineStatus`

支持一个计划部分转单。计划头状态按行状态汇总：

- `GENERATED`
- `PARTIALLY_ORDERED`
- `ORDERED`

### 6. 只汇总“可执行需求”

订单需求只纳入仍可能触发采购的订单状态：

- `PENDING`
- `CREATED`
- `CONFIRMED`
- `PAID`

不纳入已发货、已取消、已退款、审核驳回订单。补货需求只纳入 `ACCEPTED` 的补货建议，避免把待确认建议直接算进正式采购。

## API 方案

- `GET /oms/api/in/v1/orders/procurement-demand`
  用于 SCM 汇总开放订单采购需求
- `POST /scm/api/in/v1/purchase-plans/generate`
  生成采购计划
- `GET /scm/api/in/v1/purchase-plans`
  查询采购计划列表
- `GET /scm/api/in/v1/purchase-plans/{planId}`
  查询采购计划详情和计算明细
- `POST /scm/api/in/v1/purchase-plans/{planId}/purchase-orders`
  选择计划行并生成采购单草稿

## 测试策略

- 订单需求 + 已接受补货建议 + 可用库存 + 采购中数量的计算结果应正确
- 仅 `ACCEPTED` 补货建议应进入采购计划
- 已取消/已发货订单不应进入采购计划
- 采购计划转采购单后，采购单数量应等于计划建议采购量
- 采购计划部分转单后状态应正确更新，已转单行不可重复转单
