# PDM-SOM-OMS A闭环设计

## 背景

本轮默认按 `P2-007/008/014/016/019/020` 推进 `PDM -> SOM -> OMS` 纯 ERP 内闭环，不引入新的外部平台集成、PMS 入站能力或跨域事件订阅编排。目标是在现有骨架上补齐可验收的业务实现与测试证据。

当前代码现状：

- `PDM` 已具备 `SPU/SKU/选品提报/开发流程` 基础接口与存储。
- `SOM` 已具备 `Listing/ChannelSku/PriceRule` 基础接口，但缺少符合验收标准的价格计算器能力。
- `OMS` 已具备 `订单导入/风控/黑名单/履约` 基础接口，但缺少“原始订单长期保留”的明确模型与查询路径。

- Listing 创建/上下架时间
- 订单导入时间、订单下单时间

### 黄色原型

- 运营人员

- 价格测算结果

## 范围

### 本轮纳入

- `P2-007` 产品主数据：保持现有 `SPU/SKU/Brand/Category` 主流程可用。
- `P2-008` SKU映射基础：补强 `ChannelSku` 与 `Listing` 的 traceability。
- `P2-014` Listing管理：保持 CRUD/上下架能力，增加面向验收的价格测算接口。
- `P2-016` 价格计算与价格规则：实现成本、佣金、运费、目标利润率驱动的价格计算器，并叠加活动规则。
- `P2-019` 订单接入与标准化：新增原始订单留痕模型，保留入站原文与标准单据关联。
- `P2-020` 订单审核规则：补强低利润、黑名单、异常地址、重复订单等规则的可验证性。

### 本轮暂不纳入

- 外部平台真实连接器联调
- `P2-015/017/018`
- `P2-021` 以后履约链增强
- PMS入站建议打通

## 设计决策

### 1. PDM 仍作为商品主数据真相源

`SKU.sellerSku` 继续作为 SOM/OMS 引用的商品标识。SOM 不复制 PDM 的完整商品资料，仅保存：

- `Listing.productId` 指向 `SPU`
- `ChannelSku.productSku` 指向 `SKU.sellerSku`

这样能满足“内部 SKU 与渠道 SKU/Listing 可建立映射”的验收口径，同时避免在本轮引入跨域同步复杂度。

### 2. SOM 新增价格测算能力而非重做价格规则模型

保留现有 `PriceRule` 表结构与 `FIXED/PERCENTAGE/COMPETITIVE/COST_PLUS` 枚举。新增一个独立的“价格测算请求/响应”接口，由应用服务完成：

`基础售价 = (采购成本 + 运费 + 其他成本) / (1 - 佣金率 - 目标利润率)`

之后再叠加活动规则：

- `FIXED`：对结果应用上限/下限
- `PERCENTAGE`：按规则比例上浮/下调
- `COST_PLUS`：按成本加成补正
- `COMPETITIVE`：本轮仅保留扩展位，不接入真实竞品价源

返回结果中明确：

- 建议售价
- 预估利润额
- 预估利润率
- 是否触发低利润预警
- 命中的价格规则

### 3. OMS 引入原始订单快照表

新增 `oms_original_order`，用于长期保留订单接入原文和标准化关联：

- 原始请求标识
- 平台/市场/店铺
- 平台订单号
- 入站模式（API/import）
- 原始负载 JSON
- 标准化订单号
- 处理状态（IMPORTED/DUPLICATED/REJECTED）
- 去重命中信息

此设计直接补齐“原始订单长期保留”的验收缺口，同时不破坏现有 `oms_sales_order` 聚合。

### 4. 审核规则继续在 OMS 应用层集中执行

不引入新的规则引擎模块。本轮在 `OrderService` 里强化并测试：

- 高金额预警
- 买家黑名单
- 24小时重复订单
- 异常地址
- 低利润率

当命中 `MEDIUM/HIGH/CRITICAL` 风险时，订单进入 `REVIEW_REQUIRED`。

## 数据流

1. `PDM` 创建 `SPU/SKU`
2. `SOM` 建立 `ChannelSku` 映射并创建 `Listing`
3. `SOM` 通过价格测算接口给出建议售价
4. `OMS` 接收订单导入请求
5. `OMS` 先写入 `原始订单快照`
6. `OMS` 执行去重与标准化，落 `oms_sales_order/oms_order_line`
7. `OMS` 执行审核规则，生成 `oms_order_risk_check`
8. 命中风险则置为 `REVIEW_REQUIRED`

## 错误处理

- 租户缺失：统一抛 `BizException("TENANT_REQUIRED", ...)`
- SKU/产品不存在：在入口服务中尽早失败
- 重复平台订单：标准单据拒绝重复导入，但仍保留原始快照并标记 `DUPLICATED`
- 价格公式分母小于等于 0：返回业务异常，阻止生成不可用售价

## 测试策略

- `SOM`：新增价格测算单元测试，覆盖正常计算、低利润拦截、规则叠加
- `OMS`：新增订单审核回归测试，覆盖黑名单、低利润、异常地址、重复订单
- `OMS`：新增原始订单快照持久化测试，确认导入时总会写入原始记录

## 约束

- 不新增版本号依赖
- API 路径保持 `/{service-name}/api/{direction}/v1/{resource}`
- 所有路径锁定 D 盘，C 盘零写入，Maven 依赖新增需审批
