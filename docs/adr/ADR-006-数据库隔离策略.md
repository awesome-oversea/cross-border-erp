# ADR-006: 数据库隔离策略

日期：2026-05-01
状态：已采纳
决策者：技术负责人

---

## 上下文

跨境电商ERP系统需要支持多租户，14域数据需要隔离。核心需求包括：
- 多租户数据隔离
- 14域数据逻辑隔离
- 性能和成本平衡
- 未来微服务拆分兼容

---

## 决策

采用 **分阶段数据库隔离策略**：
- **一期**：单库多Schema + 租户ID字段隔离
- **二期**：关键域独立Schema，读写分离
- **三期**：关键域独立数据库实例

---

## 备选方案

### 方案A：共享数据库+字段隔离

| 优点 | 缺点 |
|---|---|
| 运维简单 | 隔离性弱 |
| 成本低 | 大租户影响小租户 |
| 开发简单 | 数据泄露风险 |

### 方案B：Schema隔离

| 优点 | 缺点 |
|---|---|
| 隔离性较好 | 运维复杂度中等 |
| 按域隔离清晰 | 跨Schema查询复杂 |
| 微服务拆分友好 | 连接池管理复杂 |

### 方案C：分阶段策略（采纳）

| 阶段 | 策略 | 隔离级别 |
|---|---|---|
| 一期 | 单库多Schema + 租户ID字段 | 逻辑隔离 |
| 二期 | 关键域独立Schema + 读写分离 | Schema隔离 |
| 三期 | 关键域独立数据库实例 | 物理隔离 |

---

## 理由

1. **一期成本优先**：单库多Schema运维成本最低，租户ID字段隔离满足一期需求
2. **域级Schema**：14域按Schema划分（iam/pdm/som/oms/scm/wms/fba/tms/crm/fms/bi/sys），逻辑清晰
3. **MyBatis-Plus多租户**：TenantLineHandler自动注入租户ID条件，开发无感
4. **微服务拆分友好**：域级Schema拆分为独立数据库时，迁移成本低

---

## 一期Schema规划

| Schema | 域 | 核心表 |
|---|---|---|
| iam | IAM | sys_tenant/sys_org/sys_user/sys_role/sys_permission |
| pdm | PDM | pdm_product/pdm_sku/pdm_sku_mapping |
| som | SOM | som_shop/som_listing/som_price_log |
| ads | ADS | ads_campaign/ads_keyword/ads_report |
| oms | OMS | oms_channel_order/oms_sales_order/oms_fulfillment_order/oms_package |
| scm | SCM | scm_purchase_order/scm_supplier/scm_purchase_item |
| wms | WMS | wms_inventory/wms_inventory_tx/wms_inbound/wms_outbound |
| fba | FBA | fba_inventory/fba_replenish/fba_shipment |
| tms | TMS | tms_carrier/tms_shipment/tms_tracking |
| crm | CRM | crm_email/crm_refund/crm_return/crm_quality_issue |
| fms | FMS | fms_payment/fms_cost_event/fms_profit/fms_settlement |
| bi | BI | bi_report/bi_kpi/bi_dashboard |
| sys | SYS/DASHBOARD | sys_config/sys_connector/sys_dict/sys_pms_suggestion |

---

## 影响

- 一期单库运维简单，但大租户可能影响性能
- MyBatis-Plus多租户拦截器需正确配置
- 跨Schema JOIN需注意性能
- 二期Schema→数据库迁移需数据迁移方案
