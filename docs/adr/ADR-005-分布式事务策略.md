# ADR-005: 分布式事务策略

日期：2026-05-01
状态：已采纳
决策者：技术负责人

---

## 上下文

跨境电商ERP系统14域之间存在跨域操作，需要保证数据一致性。核心场景包括：
- 订单创建→库存预占（强一致）
- 采购收货→库存增加→成本事件创建（最终一致）
- 发货完成→订单状态更新→物流轨迹更新（最终一致）
- PMS建议→审批→执行→反馈（最终一致）

---

## 决策

采用 **分阶段分布式事务策略**：
- **一期**：模块化单体内部@Transactional + Kafka Outbox最终一致
- **二期**：关键域服务化后启用Seata AT模式 + RocketMQ事务消息
- **三期**：事件驱动+Saga编排

---

## 备选方案

### 方案A：全Seata AT模式

| 优点 | 缺点 |
|---|---|
| 强一致保证 | 性能开销大 |
| 侵入性低 | 一期模块化单体不需要 |
| 运维简单 | 全局锁竞争 |

### 方案B：全事件驱动+Saga

| 优点 | 缺点 |
|---|---|
| 高性能 | 补偿逻辑复杂 |
| 松耦合 | 一致性窗口长 |
| 可扩展 | 开发成本高 |

### 方案C：分阶段策略（采纳）

| 阶段 | 策略 | 适用场景 |
|---|---|---|
| 一期 | @Transactional + Outbox | 模块化单体内部强一致，跨域最终一致 |
| 二期 | Seata AT + RocketMQ事务消息 | 关键域服务化后跨服务强一致 |
| 三期 | Saga编排 | 复杂长事务编排 |

---

## 理由

1. **一期模块化单体**：14域在同一进程内，@Transactional足够，引入Seata增加复杂度但无收益
2. **Outbox模式**：保证业务操作和事件发布的原子性，避免分布式事务
3. **渐进式引入**：随架构演进逐步引入更强的分布式事务能力
4. **Seata预留**：Maven依赖预留，配置预留，不启用

---

## 一期事务策略

| 场景 | 策略 | 一致性 |
|---|---|---|
| 单域内操作 | @Transactional | 强一致 |
| 跨域同步调用 | @Transactional（同进程） | 强一致 |
| 跨域异步通知 | Kafka + Outbox | 最终一致 |
| 库存预占 | @Transactional（OMS→WMS同进程） | 强一致 |
| 成本事件归集 | Kafka + Outbox | 最终一致 |
| PMS建议执行 | @Transactional + Outbox反馈 | 最终一致 |

---

## 影响

- 一期无需Seata运维
- 跨域最终一致需业务方接受延迟
- Outbox表需要定期清理
- 二期Seata启用需要数据迁移验证
