# ADR-001: 模块化单体架构与双层网关

## 状态
已采纳

## 上下文
跨境电商ERP系统需要支持14个业务域，初期需要快速交付核心闭环，同时为未来微服务化预留接口。

## 决策

### 架构形态
- 一期采用模块化单体（Modular Monolith），单进程多模块
- 按DDD分层（api/application/domain/infrastructure）组织每个域模块
- 域模块间禁止直接依赖，跨域调用走REST API或领域事件

### 双层网关
- Kong作为外部入口网关：SSL终结、域名路由、全局限流
- Spring Cloud Gateway作为内部服务网关：认证鉴权、租户Header传递、内部路由、限流熔断

### API路径规范
- `/{service-name}/api/{direction}/v1/{resource}`
- direction: in(外部→ERP) / out(ERP→外部)
- 内部域间调用走 `/api/v1/...` 或OpenFeign

## 影响
- 正面：快速交付、代码边界清晰、未来可拆分
- 负面：一期共享数据库需严格逻辑Schema隔离
- 风险：模块间耦合需通过代码审查和架构测试约束

# ADR-002: Spring Cloud Java技术栈

## 状态
已采纳

## 上下文
系统需要选择Java微服务技术栈。

## 决策
- Spring Boot 3.2.x + Spring Cloud 2023.x
- Nacos 2.3.x：服务注册与配置中心
- OpenFeign + LoadBalancer：声明式服务调用
- Sentinel 1.8.x：限流熔断
- Seata 1.8.x：分布式事务（AT模式）
- MyBatis-Plus 3.5.x：ORM与多租户插件
- PostgreSQL 15+：主数据库
- Kafka 3.6+：领域事件消息队列

## 影响
- 团队需掌握Spring Cloud生态
- Nacos提供统一配置和服务发现
- 一期Seata可暂不启用，模块化单体内部事务由Spring @Transactional管理

# ADR-003: ERP与PMS职责边界

## 状态
已采纳

## 上下文
ERP与AI选品系统PMS需要明确数据主权和写入边界。

## 决策
- ERP是经营数据真相源，所有正式业务单据由ERP创建和变更
- PMS是AI建议系统，只能创建建议/草稿/待审批动作/风险预警/洞察卡片
- PMS写入必须经过ERP权限校验和审批流
- 所有PMS调用必须记录tenant、actor、scope、purpose、trace、idempotency

## 影响
- PMS集成接口必须走SYS域入站路径 `/sys/api/in/v1/pms/recommendations`
- 审批主控原则确保ERP对业务数据的完全控制
