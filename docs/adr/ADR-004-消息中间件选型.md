# ADR-004: 消息中间件选型

日期：2026-05-01
状态：已采纳
决策者：技术负责人

---

## 上下文

跨境电商ERP系统需要消息中间件来支撑事件驱动架构，实现14域之间的异步解耦。核心需求包括：
- 高吞吐量：日订单处理≥10万，库存变更事件频繁
- 事务消息：订单→库存预占需要跨域事务保证
- 事件回放：Outbox模式需要支持事件重放
- 运维成熟度：团队对消息中间件的运维经验

---

## 决策

采用 **Kafka + RocketMQ 双消息中间件**策略：
- **Kafka** 作为主消息中间件，承载高吞吐事件驱动
- **RocketMQ** 作为事务消息中间件，承载跨域强一致场景

---

## 备选方案

### 方案A：仅Kafka

| 优点 | 缺点 |
|---|---|
| 高吞吐，成熟生态 | 事务消息支持弱（需自行实现） |
| 社区活跃，文档丰富 | 运维复杂度高 |
| 与Spring Cloud Stream集成好 | 分区管理需手动 |

### 方案B：仅RocketMQ

| 优点 | 缺点 |
|---|---|
| 原生事务消息支持 | 吞吐量低于Kafka |
| 延迟消息支持 | 社区生态不如Kafka |
| 阿里系，中文文档好 | 运维经验不足 |

### 方案C：Kafka + RocketMQ（采纳）

| 优点 | 缺点 |
|---|---|
| 各取所长 | 运维两套中间件 |
| Kafka高吞吐+RocketMQ事务消息 | 团队学习成本 |
| 灵活选择合适工具 | 资源占用更多 |

---

## 理由

1. **Kafka高吞吐**：14域事件驱动，日处理10万+订单，库存变更事件频繁，Kafka的分区和批量机制更适合
2. **RocketMQ事务消息**：订单→库存预占等跨域强一致场景，RocketMQ原生事务消息比Kafka的事务实现更简单可靠
3. **Spring Cloud Stream**：统一抽象层，应用代码不直接依赖具体中间件
4. **渐进式引入**：一期主要用Kafka+Outbox，RocketMQ事务消息按需启用

---

## 影响

- 运维需维护两套消息中间件
- 开发需理解Spring Cloud Stream抽象层
- 一期Kafka为主，RocketMQ预留
- 二期按需启用RocketMQ事务消息

---

## 主题规划

| 中间件 | 主题 | 用途 |
|---|---|---|
| Kafka | order.* / inventory.* / cost.* | 高吞吐事件驱动 |
| Kafka | outbox.event | Outbox事件发布 |
| Kafka | pms.* | PMS集成事件 |
| RocketMQ | order-inventory-tx | 订单→库存事务消息 |
