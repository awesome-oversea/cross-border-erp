# Java生态全周期技术选型方案

## 一、选型原则与核心指标





| 指标             | 说明                                         |
| :--------------- | :------------------------------------------- |
| **免费开源**     | 优先 Apache 2.0、MIT 协议                    |
| **性能**         | 单机吞吐量、并发量、延迟（P99）满足业务目标  |
| **上手难度**     | 学习成本、开发效率、社区文档完备度           |
| **社区活跃度**   | GitHub Star 数、Issue 响应速度、版本迭代频率 |
| **可扩展性**     | 支持水平扩展、可视化管控、可替换组件         |
| **可维护性**     | 配置集中管理、自动化错误处理、测试友好       |
| **稳定性**       | 连接容错、死信队列、重试与幂等机制成熟       |
| **技术栈契合度** | 与团队现有 Java/Spring 生态无缝集成          |
| **运维与监控**   | 安装部署指引、运维 Web 面板、全链路可观测    |

## 二、容器化与云原生部署选型





| 组件           | 技术                                | 适用场景                                 |
| :------------- | :---------------------------------- | :--------------------------------------- |
| **容器化**     | Docker + Dockerfile（多阶段构建）   | 应用镜像构建，安全、最小化镜像           |
| **本地编排**   | Docker Compose v3                   | 开发环境全套依赖一键启动，支持代码热加载 |
| **集群部署**   | Helm 3 + Kubernetes                 | 生产级部署、弹性伸缩、多环境管理、回滚   |
| **CI/CD 集成** | Jenkins / GitLab CI + Docker + Helm | 流水线自动构建镜像，自动部署至 K8s       |

### 容器编排对比：Docker Compose vs Helm





| 维度         | Docker Compose              | Helm                               |
| :----------- | :-------------------------- | :--------------------------------- |
| **适用场景** | 本地开发、单机部署、CI 测试 | Kubernetes 集群、生产环境          |
| **高可用**   | 无（单机）                  | 自动故障转移、多副本、自愈         |
| **弹性伸缩** | 手动                        | HPA 自动，基于 CPU/内存/自定义指标 |
| **配置管理** | 环境变量、.env 文件         | ConfigMap、Secret，多 values 文件  |
| **更新策略** | 手动重启                    | 滚动更新、灰度发布、一键回滚       |
| **存储**     | bind mount 或本地卷         | PV/PVC，云存储集成                 |
| **复杂度**   | 低                          | 需理解 Kubernetes 概念             |
| **推荐阶段** | 开发、测试                  | 预发布、生产                       |

## 三、前端技术选型





| 层级                | 技术                         | 适用场景                               |
| :------------------ | :--------------------------- | :------------------------------------- |
| **核心框架**        | Vue 3 + Element Plus         | 标准后台管理、表单与列表业务，优先选择 |
| **图编辑/拓扑分析** | React + Ant Design + AntV X6 | 工作流设计、网络拓扑、图可视化场景     |
| **复杂低代码平台**  | React + Rxdrag               | 需要 DDD 经验的复杂逻辑编排            |
| **轻量低代码表单**  | vue-form-design / AK-Design  | 快速拖拽表单搭建，小团队快速交付       |
| **移动端管理**      | React Native（后续扩展）     | 移动端监控或审批类轻量应用             |
| **可视化报表**      | JimuReport（后端集成）       | 报表设计及预览，紧密配合 JeecgBoot     |

**选择策略**：主流管理界面统一采用 Vue3 + ElementPlus，图编辑场景单独拆分 React 微前端模块。

## 四、后端技术选型

### 4.1 基础平台





| 类别               | 技术选型                          | 备注                        |
| :----------------- | :-------------------------------- | :-------------------------- |
| **IDE**            | IntelliJ IDEA（安装 Lombok 插件） | 统一开发环境                |
| **语言**           | Java 8+（兼容 17 LTS）            | 稳定、长期支持              |
| **依赖管理**       | Maven                             | 内部私有仓库代理            |
| **基础框架**       | Spring Boot 2.7.18                | 稳定版本，生产验证          |
| **微服务体系**     | Spring Cloud Alibaba 2021.0.1.0   | 含 Nacos、Sentinel、Gateway |
| **低代码基础平台** | JeecgBoot                         | 后台快速开发，代码生成      |
| **持久层**         | MyBatis-Plus 3.5.3.2              | 单表 CRUD 自动化，分页插件  |
| **报表**           | JimuReport 1.8.1                  | 集成至 JeecgBoot            |

### 4.2 服务治理与中间件





| 类别                    | 技术选型                                                     | 说明                                                      |
| :---------------------- | :----------------------------------------------------------- | :-------------------------------------------------------- |
| **服务注册 & 配置中心** | Nacos                                                        | 同时替代 Eureka + Config，支持 AP/CP 切换                 |
| **负载均衡与网关**      | Nginx 集群 + Spring Cloud Gateway（优先）/ APISIX            | Gateway 适用于中等规模；APISIX 用于多协议、高性能网关需求 |
| **服务调用**            | Forest（优先）、Retrofit + OkHttp                            | 声明式 HTTP 客户端，简化调用                              |
| **服务容错**            | Sentinel（优先）、Resilience4j                               | 限流、熔断、降级，与 Nacos 数据源打通                     |
| **分布式事务**          | Seata（Saga/AT 模式）、Redisson（分布式锁）、ZooKeeper Curator | 按业务场景混合使用                                        |
| **多级缓存**            | 本地 Caffeine + 分布式 Redis（Codis 分片）                   | 热数据双写，冷数据懒加载                                  |

### 4.3 异步与消息驱动





| 类别               | 技术选型                                                     | 定位                                    |
| :----------------- | :----------------------------------------------------------- | :-------------------------------------- |
| **业务异步解耦**   | **RocketMQ + Spring Cloud Stream**                           | 核心业务异步层，削峰填谷，事务消息      |
| **大数据日志采集** | Kafka（原生客户端 `KafkaTemplate`）                          | 高吞吐日志链路，独立通道                |
| **工作流引擎**     | N8N（优先）、Camunda、Flowable、Temporal                     | 按流程复杂度选型                        |
| **消息标准化抽象** | Spring Cloud Stream 函数式编程模型（`Supplier`/`Function`/`Consumer`） | 与中间件解耦，未来可切换至 Kafka 或其他 |

> **关键决策**：
>
> - 业务异步首选 **RocketMQ + SCS**：开箱即用的死信队列、重试、消费组、全链路追踪（集成 SkyWalking），同时兼具高性能与低延迟。
> - 日志/大数据链路保留 **Kafka 原生客户端**：追求极致吞吐和精细控制。
> - 两者可并行共存，SCS 不会成为瓶颈，且在维护性和稳定性上具有显著优势。

### 4.4 安全与数据转换





| 类别           | 技术选型                                       | 说明                               |
| :------------- | :--------------------------------------------- | :--------------------------------- |
| **认证与授权** | Keycloak + Spring Security OAuth2 + JWT        | OIDC 标准，支持 RBAC/ABAC          |
| **权限模型**   | Apache Shiro（遗留兼容）/ Spring Security 统一 | 新模块使用 Spring Security         |
| **对象映射**   | MapStruct + Jackson                            | 编译期代码生成，零反射，高性能     |
| **规则引擎**   | Drools + Elasticsearch                         | 复杂事件处理、审计日志、规则热更新 |

### 4.5 运维、监控与质量





| 类别              | 技术选型                                 | 说明                                    |
| :---------------- | :--------------------------------------- | :-------------------------------------- |
| **日志**          | Log4j2（异步） + Filebeat + ELK + Kafka  | 业务日志与大数据日志分流                |
| **链路追踪**      | SkyWalking（优先）/ OpenTelemetry        | 与 Spring Cloud Stream 自动传递 TraceID |
| **指标监控**      | Prometheus + Node Exporter + Grafana     | 资源监控                                |
| **应用健康**      | Spring Boot Admin                        | 快速查看服务状态                        |
| **持续集成/部署** | Jenkins + GitLab + Docker + Kubernetes   | 容器化流水线                            |
| **压力测试**      | JMeter / Locust                          | 定期执行                                |
| **自动化测试**    | JUnit + Mockito（单元）、Selenium（E2E） | 质量门禁                                |

## 五、基于团队规模的方案裁剪





| 维度         | 小型团队（<10人）                  | 中型团队（10-50人）                | 大型团队（>50人）               |
| :----------- | :--------------------------------- | :--------------------------------- | :------------------------------ |
| **核心架构** | Spring Boot 单体 + Gateway + SCS   | Spring Cloud 微服务 + SCS 混合原生 | 服务网格（Istio）+ 多集群       |
| **网关**     | Spring Cloud Gateway               | APISIX / Kong + 自定义插件         | Envoy + 自研控制面              |
| **配置中心** | Nacos 单节点（测试）/ 集群（生产） | Apollo 集群                        | 多级缓存 + Apollo 异地同步      |
| **异步层**   | RocketMQ + SCS（默认配置）         | RocketMQ + SCS（调优并发、DLQ）    | Kafka 原生 + SCS 混合，分层治理 |
| **映射引擎** | Groovy 动态脚本 + Caffeine         | JRuby 预编译                       | GraalVM 原生编译 + 规则热替换   |
| **调用量**   | 百万级/日                          | 千万级/日                          | 亿级/日                         |
| **响应时间** | <100ms (P99)                       | <50ms (P99)                        | <30ms (P99)                     |
| **部署**     | 2 节点（云主机 + 同城灾备）        | 5 节点集群 + 异地只读副本          | 多云多活架构                    |
| **实施周期** | 1 个月基础功能                     | 3 个月含监控体系                   | 6 个月全链路治理                |
| **容器编排** | Docker Compose                     | Helm + Kubernetes                  | Helm + 服务网格 + GitOps        |

## 六、全生命周期演进路线

### Phase 1：基础平台

- 搭建 Nacos 集群、Spring Cloud Gateway
- 业务服务通过 **RocketMQ + Spring Cloud Stream** 实现核心异步解耦
- 集成 SkyWalking 链路追踪、Prometheus 基础监控
- 部署同城双活（华为云），使用 Nginx 做基本负载均衡
- 测试环境使用 Docker Compose 一键启动环境
- CI 流水线集成 Docker 镜像构建与推送

### Phase 2：能力增强

- 可视化低代码配置界面（Vue3 + Element Plus）
- 引入 Drools 规则引擎，实现业务规则动态下发
- 灰度发布系统、Feature Toggle 集成
- 移动端管理 APP（React Native）
- 消息层优化：启用 SCS 批处理、原生序列化，按需混用原生客户端
- 生产环境迁移至 Helm + Kubernetes，实现弹性伸缩与滚动更新

### Phase 3：智能演进

- 自动熔断容量评估系统，与 Sentinel 联动
- 多云管理平面（华为云 + 阿里云）
- 向服务网格架构平滑演进（Istio + Envoy）
- 全链路终态：SCS 作为统一消息抽象，底层按业务属性路由至 RocketMQ 或 Kafka
